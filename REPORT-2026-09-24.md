## What was built and merged

### Recursive unpacking — PR #7 (merged)
Stage 0 unpacks containers before triage, into a bounded node tree.
- ZIP (including nested and AES-encrypted, trying the usual sample passwords) and DMG.
- DMG: uses 7-Zip when present; otherwise a built-in UDIF decoder (zlib, bzip2, ADC, LZMA, raw) rebuilds
  the disk image and carves thin/fat Mach-O binaries out of it.
- Guards against zip bombs, path traversal, symlinks, and runaway depth/size. Duplicate files are
  analyzed once. The most analyzable file is auto-selected as the primary target.
- Fixed a real bug it surfaced: an uncompressed DMG was being detected as a Mach-O because leading magic
  was checked before the `koly` trailer.

### Repository governance and CI
- `main` is protected: changes must go through a PR, three CI checks (lint, test, sample-guard) must pass,
  and force-pushes and branch deletion are blocked. Verified by a rejected direct push.
- CI runs `ruff`, `pytest`, and a **sample-guard** job that fails if any executable, archive, or disk image
  is ever committed. Test fixtures are generated in code, so the repo holds no binaries.
- Added CODEOWNERS, a PR template with a safety checklist, issue forms, Dependabot, secret scanning and
  push protection, private vulnerability reporting, and CodeQL.
- Added `AGENTS.md` (architecture invariants for coding agents) and `CLAUDE.md`.

### Verified agent loop + evidence brief — PR #9 (merged)
The core loop had never actually run. Exercising it end-to-end turned up two real bugs:
- **The agent couldn't see most of the static analysis.** Its first message was the raw evidence JSON cut
  at 12,000 characters, which dropped capa/Ghidra output and the string sample. Replaced with a structured
  brief (`malloop/brief.py`): each section is compacted on its own budget, and the least useful material
  shrinks first to fit `MALLOOP_MAX_INITIAL_EVIDENCE_CHARS` (default 60000).
- **A malformed PE header crashed the whole run.** Now recorded in the triage report instead.
- Added the `read_file` tool so the agent can read scripts/configs in full (text, or hex for binary),
  instead of dumping fragments through the string search.
- Made the loop testable without an API key or VM: `run_agent`/`cli.analyze` accept an injected client and
  sandbox. Two end-to-end test files drive the real pipeline with a scripted model and a fake VM, including
  a prompt-injection string checked to never escape the `<untrusted>` wrapper.

### REMnux static worker — PR #10 (open)
capa and FLOSS are the heavy stage-2 tools and aren't installed on the host. This runs them inside an
isolated Linux VM (REMnux) over the host-only network, mirroring the detonation-guest pattern.
- `malloop/worker/worker_agent.py`: stdlib-only HTTP server for inside the VM. It parses samples with
  capa/FLOSS and returns JSON; it never executes them.
- `malloop/static_worker.py`: host client. An unreachable worker degrades to a per-tool error, not a crash.
- `static_analysis.run_static(...)` routes through the worker when `MALLOOP_STATIC_WORKER_URL` is set, else
  runs the tools locally as before. Ghidra and YARA stay on the host.
- Both HTTP agents now drain the request body before rejecting a bad token, so a rejected upload gets a
  clean 403 instead of a connection reset (a bug the worker work surfaced in the guest agent too).

## Live testing against real samples

Using the Claude API (`claude-opus`), the full loop was run on real files from `Downloads`. Static-only
(no detonation — nothing is executed on the host). Representative results:

| Sample | Verdict | Notes |
|---|---|---|
| `Totally Harmless File.exe`, `payload.exe`, `encryptor.exe` | malicious (0.9–0.95) | Identified as the same custom AES-256-GCM ransomware family |
| `privesc_lab.exe` | malicious (0.85) | UAC-bypass tool (fodhelper/sdclt registry hijack) |
| `CORRUPTED BOOST PREMIUM.zip` | suspicious (0.8) | Discord mass-DM spam bot (read all Python source via `read_file`) |
| `procdump64.exe` | benign (0.85) | Correctly identified as legitimate Sysinternals ProcDump |
| `FilterKeysSetter.exe` | benign (0.85) | Small legitimate accessibility utility |

These runs also drove the sandbox-availability and `read_file` fixes in PR #9.

### capa/FLOSS proven running in REMnux
The hardened REMnux VM was brought online and the worker deployed into it. Running malloop against
`Totally Harmless File.exe` through the worker returned **35 real capabilities with ATT&CK IDs** from capa
executing inside the VM — RC4 and BCrypt encryption (T1027), DNS resolution, socket send/receive, registry
and process creation, and memory-protection changes. The static report is stamped
`worker: http://192.168.56.20:8766`, confirming the analysis ran in the VM over the host-only network, not
on the host.

## Sandbox VM state

The only VM on the machine is `vm`, a REMnux (Ubuntu 24.04) image. It was hardened for sample work:
- Networking switched from NAT to **host-only** (no internet).
- The global shared folder mapping the host `Downloads` into the VM was removed.
- Clipboard and drag-and-drop disabled.
- Snapshots: `clean baseline` → `pre-malloop-hardening` → **`malloop-hardened`** (use this one; the older two
  still have NAT and the host share).

Getting the worker running required working around a dead Guest Additions stack (v6.0.0 vs VirtualBox
7.2.8): no guest file-copy, no guest clipboard. The console was driven via VirtualBox hardware-keyboard
injection. `dhclient` is absent on Ubuntu 24.04, so the guest was given a static IP (`192.168.56.20`), and
the worker file was pulled over a short-lived host HTTP server.

**Current runtime state:** the worker is running at `192.168.56.20:8766` (token `malloopstatic`). This
resets on VM reboot — the worker runs in the foreground and the static IP isn't persisted. It can be made
permanent with a systemd service.

Run a sample through it:
```bash
cd /c/Users/elevation/Downloads/malloop
MALLOOP_SANDBOX=none \
MALLOOP_STATIC_WORKER_URL=http://192.168.56.20:8766 \
MALLOOP_STATIC_WORKER_TOKEN=malloopstatic \
ANTHROPIC_API_KEY=... \
.venv/Scripts/python -m malloop analyze "path/to/sample.exe"
```
